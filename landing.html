Grammar Architecture

Three ANTLR4 Context-Free Grammars powering the translator

① Structural Asymmetry

Java uses braces for blocks; Python uses indentation. The Java grammar skips whitespace entirely (NL → skip). The Python grammar must capture newlines and the leading spaces that follow them — this is how the parser knows a new indented block began.

java2py.g4 — whitespace-agnostic

program: classDef EOF;
classDef:
  PUBLIC CLASS ID
  '{' classBody '}';
classBody: methodDef*;
methodDef:
  PUBLIC STATIC javaType
  ID '(' param? ')' block;
block: '{' stmt* '}';

// whitespace discarded
NL: ('\r'? '\n' [ \t]*) -> skip;
WS: [ \t]+ -> skip;

py2java.g4 — indentation preserved

program: (stmt | NL)+ EOF;
stmt: ifStmt
    | whileStmt
    | forStmt
    | funcStmt
    | asg | printStmt
    | returnStmt | ...;
block: NL stmt+; // indent = scope

// newline + spaces = token
NL: ('\r'? '\n' [ \t]*);
WS: [ \t]+ -> skip;

② Operator Precedence via Rule Nesting

No explicit precedence directives are needed. Precedence emerges structurally: lower-priority operators (and/or) live at the top of the hierarchy; higher-priority operators (*/) are nested deeper, so they are reduced first by the LL(*) parser. 

// Identical hierarchy in both grammars
exp      : logicExp;
logicExp : compExp (op=('and'|'or') compExp)*;
compExp  : addExp  (op=('>'|'<'|'=='|'!=') addExp)*;
addExp   : mulExp  (op=('+'|'-') mulExp)*;
mulExp   : unaryExp (op=('*'|'/') unaryExp)*;
unaryExp : op=('not'|'-') unaryExp | atom;
atom     : NUMBER | FLOAT | STRING
         | TRUE | FALSE | NONE
         | ID '(' (exp (',' exp)*)? ')'
         | ID | '(' exp ')';
PPL insight: Rule depth encodes precedence. mulExp is deeper than addExp, so 2 + 3 * 4 parses as 2 + (3 * 4) automatically.

③ Command DSL Grammar

A third grammar (command.g4) recognises natural-language chat commands. Every request is tried against this grammar first. If the visitor returns "0" it's not a command, so the server routes it to the code translator instead. 

// command.g4
program : command+ EOF;
command : verb noun* target? | non_command;
verb    : 'show'|'save'|'store'
        | 'translate'|'retrieve'|'get';
target  : source TO target_lang;
source  : PYTHON | JAVA;
target_lang: PYTHON | JAVA;

TO:     'to';
PYTHON: 'python';
JAVA:   'java';
ID:     [a-zA-Z_][a-zA-Z0-9_]*;
WS:     [ \t\r\n]+ -> skip;
Input → "translate python to java"
returns "pytojava"
Input → "show grammar"
returns "showgrammar"
Input → "save code"
returns "savecode"
Input → "show output"
returns "showoutput"

④ Loop Grammar — Asymmetric Translation

Python's range() and Java's triple-header for are structurally different. The grammars capture this asymmetry explicitly, letting the visitor produce the correct idiom in each direction.

py2java — range rule

forStmt:
  FOR ID IN
  rangeExp COLON block;

rangeExp:
  RANGE '('
    exp
    (',' exp
      (',' exp)?)?
  ')';

java2py — C-style for

forStmt:
  FOR '('
    javaType ID '=' exp ';'
    exp ';'
    postfixStmt
  ')' block;

// No range equivalent —
// visitor emits while loop

Visitor Pattern & Type Inference

Walking the Concrete Syntax Tree to emit the target language

Why Visitor Pattern?

The Visitor pattern decouples translation logic from grammar structure. Each visitX method handles exactly one grammar rule in isolation — adding a new construct means adding a new method, not touching existing ones.

▸ visitProgram — collects all top-level statements
▸ visitStmt — dispatches to the right sub-visitor
▸ visitIfStmt / visitForStmt / ... — emit target syntax
▸ visitAtom — handles literals, identifiers, calls

Type Inference Engine

Python→Java requires inferring a static type for every assignment. inferType() walks the expression subtree bottom-up — no separate analysis pass. 

# py2javaVisitor.py
def inferType(self, ctx):
    if isinstance(ctx, AtomContext):
        if ctx.STRING(): return "String"
        if ctx.FLOAT():  return "double"
        if ctx.TRUE() or ctx.FALSE():
                         return "boolean"
        if ctx.NONE():   return "Object"
        if ctx.NUMBER(): return "int"
    if isinstance(ctx, LogicExpContext):
        if ctx.op:       return "boolean"
    if isinstance(ctx, CompExpContext):
        if ctx.op:       return "boolean"
    # recurse into sub-expression ...
    return "int"  # default fallback

Indentation Tracking (Java→Python)

Python requires syntactically correct indentation. The Java→Python visitor maintains an indent_level counter — incremented on block entry, decremented on exit — so emitted Python is structurally valid, not post-processed. 

# java2pyVisitor.py
class java2pyVisitor:
    def __init__(self):
        self.indent_level = 0

    def indent(self):
        return "    " * self.indent_level

    def visitWhileStmt(self, ctx):
        cond = self.visit(ctx.exp())
        self.indent_level += 1
        body = self.visit(ctx.block())
        self.indent_level -= 1
        return (f"{self.indent()}while {cond}:\n"
                f"{body}")

Loop Translation — Both Directions

Python → Java (range → triple-header for)

Input (Python)

for i in range(1, 6):
    print(i)

Output (Java)

for (int i = 1; i < 6; i++) {
    System.out.println(i);
}

visitRangeExp unpacks the 1–3 arguments of range() and emits the correct init/condition/update triplet.

Java → Python (C-style for → while)

Input (Java)

for (int i=0; i<5; i++) {
    System.out.println(i);
}

Output (Python)

# Converted from Java for loop
i = 0
while i < 5:
    print(i)
    i += 1

Python has no direct equivalent of C-style for, so the visitor decomposes it into init + while + trailing increment.

Full Translation Example — Python → Java

Input — Python

def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)

if __name__ == "__main__":
    print(factorial(5))

Output — Java (type-inferred)

public static int factorial(int n) {
    if (n <= 1) {
        return 1;
    }
    return (n * factorial((n - 1)));
}
public static void main(String[] args) {
    System.out.println(factorial(5));
}
Type Inference Parameter n → int; return literal 1 → int. Multiplication propagates type.
Main Block if __name__ == "__main__" is matched by the special MAIN lexer token → emits main(String[] args).
Print Mapping visitPrintStmt maps Python's print() to Java's System.out.println().

Frontend Architecture

Multi-Conversation State

Each conversation gets a UUID as its conversation_id. The backend stores per-conversation context in memory; the frontend persists conversation history in localStorage so sessions survive page refresh.

Single API Endpoint

All interactions — code, commands, saves, tree requests, execution — go to POST /convert with a conversation_id. The response's type field (converted_code, grammar, output, message) drives how the UI renders the result.

Tech Stack

React 18 · Vite 5 · Tailwind CSS 3 · No additional state libraries. Chat messages are plain component state; code blocks are syntax-highlighted client-side.
