# Backend — JavaPy-Translator

FastAPI server that exposes a single `POST /convert` endpoint, powered by ANTLR4 grammars (Python → Java, Java → Python, and a small command DSL).

---

## Layout

```
backend/
├── server.py              # FastAPI app (POST /convert, GET /conversation/{id}/context)
├── run.py                 # CLI: regenerate grammars / run sample tests
├── requirements.txt
├── antlr_jar/
│   └── antlr4-4.9.2-complete.jar
├── grammars/              # ANTLR sources (.g4)
│   ├── py2java.g4
│   ├── java2py.g4
│   └── command.g4
├── CompiledFiles/         # Lexer/Parser/Visitor generated by ANTLR (committed)
├── logic/                 # Translation logic (visitor implementations + tree printers)
│   ├── py2javaVisitor.py
│   ├── java2pyVisitor.py
│   ├── commandVisitor.py
│   ├── tree_printer_py.py
│   └── tree_printer_java.py
└── tests/                 # Sample inputs for run.py (001.txt, 002.txt, 003.txt)
```

---

## Prerequisites

- **Python 3.8+**
- **Java JDK 8+** — required if you (a) regenerate grammars or (b) want `show output` to run translated Java code via `javac` / `java`.
- The ANTLR jar is already vendored at `antlr_jar/antlr4-4.9.2-complete.jar`. No extra download needed.

## Setup

You can run the backend either inside a **virtual environment** (recommended) or directly against your **local Python**. Pick one.

### Option A — Virtual environment (`.venv`) — recommended

From the `backend/` directory:

**macOS / Linux**
```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

**Windows (PowerShell)**
```powershell
cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

To leave the venv later: `deactivate`.

### Option B — Local Python (no venv)

If you'd rather install into your global/user Python:

```bash
cd backend
pip install -r requirements.txt
```

Or install dependencies explicitly:

```bash
pip install fastapi pydantic uvicorn antlr4-python3-runtime==4.9.2
```

> Tip: on macOS/Linux you may need `pip3` instead of `pip`, and `python3` instead of `python`.

## Run the server

From `backend/` (with the venv activated, if you use one):

```bash
uvicorn server:app --reload
```

Expected output:
```
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
INFO:     Started reloader process
```

- API base: `http://localhost:8000`
- Swagger docs: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`

If port `8000` is in use:
```bash
uvicorn server:app --reload --port 8001
```
(then point the frontend at the new port — see `frontend/services/api.js`).

You can also start it from `server.py` directly:
```bash
python server.py
```

## API

### `POST /convert`

Request body:
```json
{
  "code": "def hello():\n    print(\"Hi\")\n",
  "conversation_id": "abc-123"
}
```

The endpoint accepts either source code **or** a chat command (e.g. `translate python to java`, `show grammar`, `save code`). Auto-detects language when no direction is set on the conversation.

Response shape (varies by `type`):
```json
{
  "result": "<translated code | parse tree | message>",
  "type": "converted_code | code | grammar | output | message",
  "message": "<friendly status string>",
  "conversation_id": "abc-123",
  "direction": "pytojava | javatopy"
}
```

### `GET /conversation/{conversation_id}/context`
Returns whether the conversation has saved code, the current direction, and a short preview of the last input.

## CLI helper (`run.py`)

A small driver for regenerating parsers and running grammar smoke tests.

```bash
python run.py gen                     # Regenerate all three grammars into CompiledFiles/
python run.py test py                 # Run Python -> Java on tests/001.txt
python run.py test py 001.txt         # Run Python -> Java on a specific file
python run.py test java 002.txt       # Run Java -> Python
python run.py test command 003.txt    # Run command grammar
```

`gen` uses the bundled jar at `antlr_jar/antlr4-4.9.2-complete.jar`, so you don't need to install ANTLR system-wide.

## Regenerating grammars manually

Only required if you edit a `.g4` file in `grammars/`. From `backend/`:

```bash
java -jar antlr_jar/antlr4-4.9.2-complete.jar \
  -o CompiledFiles -no-listener -Dlanguage=Python3 -visitor \
  grammars/py2java.g4

java -jar antlr_jar/antlr4-4.9.2-complete.jar \
  -o CompiledFiles -no-listener -Dlanguage=Python3 -visitor \
  grammars/java2py.g4

java -jar antlr_jar/antlr4-4.9.2-complete.jar \
  -o CompiledFiles -no-listener -Dlanguage=Python3 -visitor \
  grammars/command.g4
```

The simpler way: `python run.py gen`.

## Troubleshooting

- **`ImportError: ... CompiledFiles ...`** — the generated parsers are missing. Run `python run.py gen` (needs the JDK).
- **`Java compiler (javac) not found`** when using `show output` — install a JDK and ensure `javac` / `java` are on your `PATH`.
- **CORS / connection errors from the frontend** — make sure `uvicorn` is running on `:8000` and the frontend's `services/api.js` points at the same host/port.
- **`Address already in use`** — start uvicorn on another port: `uvicorn server:app --reload --port 8001`.
